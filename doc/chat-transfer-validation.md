# 手动聊天导入导出

实现与验收日期：2026-09-17。本次只处理聊天记录迁移，Memory 系统另行实施。已核对已发布的 v3.5.2 不含此导入导出功能；以下是首次发布前的兼容设计与验证。

## 使用方式

现有 Export 菜单提供“导出当前会话文件”“导出当前论文全部会话”“导出当前文库全部会话”和“导入聊天记录文件”。默认选项“包括图片和附件”导出 `.aidea-chat.zip`；“仅导出文字”仍导出 `.aidea-chat.json`。保存前显示会话数、去重资源数和文件大小。导入前显示新增、重复、冲突、待关联文献和标题差异的数量；确认后在事务内重新计算并合并。

## 兼容与合并规则

- 保留原来的数字 ID、消息正文、父子关系和历史表。升级时增加永久 UUID，后续新记录也自动获得 UUID。设备编号不参与去重。
- 首次迁移先把聊天表和分支状态保存到 Zotero 数据目录的 `aidea-chat-backups/before-uuid-*.json`，读回校验成功才修改数据库。失败时回滚，原有聊天仍可使用；导入导出会报告失败。此本地恢复备份与便携归档是两种格式。
- 按会话 UUID、消息 UUID 识别同一记录；升级前的记录另保存一次性的旧记录来源标识 `legacy_key`。父消息关系恢复每一条对话序列，兄弟分支顺序随归档保存。不能靠时间或内容相似度合并独立会话。
- 两端追加的消息都保留。同 UUID 内容冲突时增加分支，并保留原始身份，重复导入不重复添加冲突分支。已有会话保留本地当前分支，新会话恢复归档中的当前分支。不传播删除，不覆盖本地标题。
- “旧副本”指同一旧数据库在两台设备上的复制版本，不是合并时另存的一套聊天。升级使用原会话类型、数字 ID、创建时间、文献 key、首消息 ID 和时间生成固定版本的来源标识；消息标识另包含原消息 ID、时间和角色。原始身份信息完整的两个副本即使分别升级、UUID 不同，也合并到同一个会话，两端新增内容和编辑冲突保留为分支。合并不额外创建“旧会话”容器。
- 来源标识只为升级时已有的记录生成，后续不因编辑而重算；新记录直接使用永久 UUID。没有可靠时间、空会话，或原始 ID/首消息已被重排或删除的独立旧副本，不能保证自动识别。不能仅凭标题、相似正文强行合并，否则会丢掉真正独立的对话。
- 迁移前恢复备份独立于聊天历史，只在需要迁移或恢复旧数据时生成，正常启动和重复导入不会反复生成。它用于故障恢复，不作为重复会话展示；本次不自动删除该备份。
- 文献匹配使用 Zotero 用户/群组身份与条目 key，不使用本地数字 ID。无法匹配的文献会话进入全局历史，并标记“文献待关联”；保留原来源信息。没有 Zotero 账号身份时不猜测跨设备文献对应关系。
- 找不到原论文的历史仍可随个人文库导出，不因文献已永久删除而漏掉消息。

## 文件范围与限制

- 包含全部已保存分支、角色、正文、时间、模型名、选中文本与引用摘录。
- ZIP 包含 `chat.json`（版本 2）与 `resources/<SHA-256>`。截图、上传图片、回答内嵌的本地 data-URL 图片，以及用户上传的附件按内容去重；不下载远程图片链接，不重复打包 Zotero 管理的论文原件。已丢失的文件继续显示缺失说明。
- 导入时恢复截图和内嵌图片，上传附件写入本机管理的附件目录。先导入文字版、再导入完整版时，给同一消息补回资源；真实资源冲突保留为分支，不覆盖原图。附件文件丢失或损坏时可通过重新导入恢复。
- 便携引用保留文献来源、引用摘录、PDF 页位置或 EPUB 原生位置，以及对应原文的 SHA-256。接收端按 Zotero 文库身份和条目 key 关联文献；点击时重新验证文件内容，完全一致才使用位置。设备路径、修改时间和本地数字 ID 不必一致。
- 原文尚未同步或已替换时不使用旧位置，显示无法跳转的说明。同文库尚未同步的条目保留 key，条目和原文到齐后可再次点击校验。原记录没有可靠位置或导出时无法确认原文版本的，只保留来源，不能事后猜页码。导入旧归档可以补充资源，但不会擦掉已有的新位置元数据。
- 普通来源引用（没有位置哈希）同样保留待同步条目的 key 和文库标识；重复导入时重新补全来源关联，不新增重复消息。群组引用恢复群组 ID，使笔记和导出链接使用群组文库路径。仅补全来源时保留已有图片、附件，以及仍绑定到同一本地条目的原生位置。
- 不导出设置、密钥、缓存、Memory 或本地附件路径。用户主动写入消息正文的内容仍属于正文。
- 兼容版本 1 JSON。JSON 清单最多 50 MiB、5,000 个会话、100,000 条消息；单个资源最多 32 MiB，ZIP、解包总量与恢复资源的累计大小各限制为 128 MiB。超限明确报错，可改选仅文字或缩小会话范围。不截断后静默导入。
- 导入校验资源 SHA-256、长度、消息关系、资源位置及 ZIP 条目路径；拒绝缺失资源、重复文件名和超限解包。附件写入失败时回滚聊天数据库；失败前已写出的无引用资源文件可能留在管理目录，不会使半条对话出现在历史中。
- 旧版 Markdown/笔记导出缺少身份和分支信息，不能作为这种归档导入。待关联会话自动从全局历史搬回论文、置顶状态同步与自动云端同步不在本次范围。

## 后续版本的兼容约束

- 不重建历史表，不重排已有数字 ID，不重新生成已有 UUID 或 `legacy_key`。数据库迁移先验证备份，再在事务内执行；失败保留原聊天使用能力。
- 归档版本 1（文字）和版本 2（含资源）继续可读；新增引用位置和旧记录来源标识均为可选字段。旧记录没有这些字段时不猜测补填。
- 不支持的归档版本、无效父子关系、资源校验失败必须明确拒绝，不能部分吞掉记录后报告成功。新协议有破坏性变化时增加版本并保留已有版本的读取路径。
- 合并不传播删除；本地当前分支和已有标题优先，真实内容冲突保留分支。重复导入必须幂等，文字版升级到资源版或补充定位信息不能新增重复消息。

- 多个引用的复制／笔记导出共用本次操作的原文哈希；同一文献对象的并发校验也共用运行中的任务。操作完成后不长期缓存哈希，下次仍检查原文，避免文件替换后继续使用旧位置。
